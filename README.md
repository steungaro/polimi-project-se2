# Software Engineering 2 - Politecnico di Milano
**Project:** Best Bike Paths (BBP)

**Final Evaluation:** 13.9 / 14

## The Assignment
This repository contains the documentation produced for the Software Engineering 2 course project. The objective of the project was to simulate a real-world software engineering lifecycle. Starting from a rough, high-level specification document provided by the professors, our team was tasked with analyzing the problem domain, defining strict requirements, and designing a complete, scalable software architecture.

The case study for our academic year was **Best Bike Paths (BBP)**: a crowdsourced platform designed to help cyclists map safe routes by tracking GPS data and automatically detecting road anomalies (like potholes) via smartphone sensors.

## Project Phases
The project is divided into two main phases and deliverables:

* **RASD (Requirements Analysis and Specification Document):** The "what" of the system. In this phase, we modeled the problem domain, defined user scenarios and use cases, and formalized the functional and non-functional requirements. We also used the Alloy modeling language to formally verify the core logic of the system (specifically, how user-generated path data is aggregated and validated).
* **DD (Design Document):** The "how" of the system. We translated the requirements from the RASD into a concrete software architecture. This involved creating component and deployment diagrams, defining the database schema, detailing API interfaces, and designing the basic UX/UI wireframes.
